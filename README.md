# 论证稳定性沙盘（Argument Stability Sandbox）

一个用于构建和检验论证网络的 Web 应用。用户可以创建**观点**与**证据**节点，拖拽连线标记为**支持**或**反驳**并设置权重；系统会从节点初始可信度出发，在允许有向环的图上进行同步迭代传播。收敛后显示最终可信度；若检测到持续振荡，则停止计算并高亮导致振荡的负反馈环。每次计算后还可用**传播回放**逐轮回看：画布按当轮可信度着色、显示相邻轮升降，选中节点可核对下一轮值的完整分解。此外还提供**边权敏感性扫描**：选择一条连线与一个目标节点后，服务端在不保存图的前提下把该边权从 0 到 1 等距取 21 个值分别计算，前端以曲线展示目标节点的最终可信度，并标出首次跨过 0.5 的阈值区间。还提供**影响路径追踪**：选择一个目标节点和起始证据后，服务端枚举至多 8 跳的有向简单路径（遇重复节点立即截断以避免环），按支持/反驳符号与边权的乘积计算路径影响分数，返回绝对影响最大的前 3 条路径及其净符号，并在画布上高亮选中路径。另有**证据贡献分摊**：选择一个观点与至多 8 个证据后，服务端在内存中对全部 2ⁿ 个证据联盟重算传播（未加入联盟的所选证据从图副本删除），以空联盟为基准按精确 Shapley 公式分摊“全联盟 − 空联盟”的目标值差，前端以瀑布条展示各项有符号贡献与占比，点击条形可在画布上高亮对应证据；仅当全部联盟收敛时才给出分摊。还有**必经链路分析**：选择一个目标观点后，服务端在当前画布的有向图上对每个能到达目标的证据，按“删除后不可达”精确求出其所有有向路径共同经过的节点与连线（证据自身与目标不计瓶颈；环被严格处理，不靠枚举有限条路径近似），按瓶颈覆盖的证据数降序、节点优先于连线、id 升序稳定返回，无法到达目标的证据另列；点击侧栏瓶颈条目即在画布上高亮该瓶颈、目标与覆盖证据。最后提供**一键整理布局**：可锁定任意节点位置后预览整理效果——先把有向图中的强连通分量压缩为 DAG、按最长路径分层、固定执行 4 轮重心排序减少跨层连线交叉，同一强连通分量内的节点围绕分量中心排成圆；锁定节点坐标完全不变并作为相邻层锚点，预览确认后才一次性应用并保存。

## 唯一启动命令

确保已安装 Docker Engine 与 Docker Compose Plugin，然后在项目根目录执行：

```bash
docker compose up --build
```

启动成功后访问：

- 地址：<http://localhost:8080>
- 端口：容器内固定 `8080`，宿主机默认映射 `8080:8080`

后台运行可使用：

```bash
docker compose up --build -d
```

停止并保留 SQLite 数据：

```bash
docker compose down
```

容器内置了基于 `GET /api/health` 的健康检查，可用以下命令查看状态（`healthy` 即服务就绪）：

```bash
docker compose ps
```

## 必要配置

通常无需任何配置。只有想改变宿主机访问端口时，复制 `.env.example` 为 `.env` 并修改：

```env
APP_PORT=8080
```

例如改为 `APP_PORT=3000` 后访问 <http://localhost:3000>。

其他运行时环境变量：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8080` | 容器内 HTTP 端口，一般不需要修改 |
| `DATABASE_PATH` | `/app/data/argument.db` | SQLite 数据库文件路径 |

数据保存在 Docker named volume `argument-sqlite-data` 中。应用首次启动会自动创建数据库、表结构以及一张空白图；镜像构建阶段已经安装全部前后端依赖并完成构建。

## 使用指南

1. 点击顶部 **＋ 观点** 或 **＋ 证据** 创建节点。
2. 从节点右侧连接点拖到另一个节点左侧连接点创建连线。
3. 点击节点，可编辑名称、类型、初始可信度（0–100%）以及是否固定。
4. 点击连线，可在“支持 / 反驳”之间切换并调整权重。
5. 点击 **运行稳定性分析**：
   - 绿色状态表示达到收敛阈值；
   - 红色状态表示持续振荡或达到上限仍明显不稳定；
   - 节点显示最终可信度及相对变化；
   - 振荡时红色脉冲节点与加粗红色边标出负反馈环。
6. 计算完成后，画布左下角出现**传播回放**控制条（详见下节）。
7. 使用 **导出 JSON** 保存当前图，使用 **导入 JSON** 恢复。
8. 可先载入“稳定示例”或“振荡示例”观察两种结果。
9. 在右侧**边权敏感性扫描**卡片中选择一条连线与一个目标节点，点击 **运行边权扫描**（详见下下节）。
10. 在右侧**影响路径追踪**卡片中选择起始证据、目标节点与最大跳数（1–8，默认 8），点击 **运行路径追踪**（详见下节）。在画布上点击证据节点会自动设为起点，点击观点节点会自动设为目标。
11. 点击节点右上角的 **📍**（或检查器中的「整理布局时锁定该节点坐标」）锁定任意节点，然后点击顶部 **🧭 一键整理布局** 预览整理结果（详见下节）。
12. 在右侧**证据贡献分摊**卡片中选择一个目标观点并勾选 1–8 个证据，点击 **运行贡献分摊**（详见下节）。
13. 在右侧**必经链路分析**卡片中选择一个目标观点，点击 **运行必经链路分析**，再点击任一瓶颈条目查看画布高亮（详见下节）。

## 传播回放

每次计算完成后，画布左下角的回放条可回看**第 0 轮（先验）到停止轮**的完整过程：

- **迭代滑杆**：拖动即可跳到任意轮次。画布按该轮可信度为节点着色（红 → 黄 → 绿），节点内的数值、色条同步更新，并显示相对上一轮的升降（▲/▼ 或“持平”）。
- **播放 / 暂停**：点击 **▶ 播放** 从当前轮逐轮前进（约每 0.8 秒一轮）。收敛结果播到停止轮自动停下，再按一次从第 0 轮重播；振荡结果则按检测到的周期在最后一个周期内**循环播放**（控制条上显示“周期 N 循环”徽标）。
- **下一轮值分解**：计算后点击任意节点，侧栏会展示「当前轮 → 下一轮」的可核对分解：
  - 先验 p 与本次计算实际使用的 λ；
  - 每条入边的有符号贡献（支持为正、反驳为负，即 ±权重 × 源节点当轮值）及其合计；
  - 裁剪前的值 `p + λ·Σ`；
  - 0..1 裁剪量（超出上界裁去多少 / 低于下界抬升多少 / 未裁剪）；
  - 底部核对行：前端用同一公式独立重算，与服务器记录的下一轮值逐位比对，显示“✓ 一致”。
  - 若当前已停在最后一轮，则展示最后一次迭代的分解。
- **固定节点**：分解卡片会明确显示其值由先验锁定（🔒），入边不参与计算，因此**不列出任何入边贡献**，不伪造数据。
- **无副作用**：拖动滑杆、播放、暂停都只是前端视图切换——不会修改图、不会触发重新计算或自动保存；回放状态不写入 SQLite，刷新页面后自然消失（图本身仍会持久化）。
- 任何图编辑（增删节点/连线、改权重等）都会使本次计算结果与回放失效，需重新运行分析。

## 边权敏感性扫描

右侧栏的**边权敏感性扫描**卡片用于检验单条边权变化对某个节点结论的影响：

1. 在「扫描连线」下拉中选择一条连线（在画布上点选某条连线会自动带入，并默认把该连线的目标节点作为扫描目标）；
2. 在「目标节点」下拉中选择要观察的节点；
3. 点击 **运行边权扫描**。服务端把该边权从 **0 到 1 等距取 21 个值**（0、0.05、…、0.95、1），对每个取值在内存中复制一份图、**沿用当前传播参数**（收敛阈值 / 最大迭代 / λ）独立计算，**整个过程不保存图、不写 SQLite、不影响画布**。

曲线说明：

- 横轴为被扫描边的边权，纵轴为目标节点的最终可信度（0–1）；0.5 处有虚线判定线。
- 三类采样点用不同标记分开：**● 收敛**（蓝色实心圆，点之间连成实线曲线）、**◆ 振荡**（红色空心菱形）、**■ 达到上限**（橙色空心方块）。振荡点与上限点没有可信终值，单独落在曲线下方的“无值”刻度上，**不参与连线**。
- **阈值区间**：在连续的收敛采样点之间，目标值首次从 0.5 的一侧跨到另一侧时，用蓝色色带标出该相邻采样区间（如边权 0.35–0.40），并在图下注明两端数值。振荡点或未收敛点会打断连续性，**绝不参与跨越判断**——即便它们的末轮值碰巧越过 0.5 也不会产生阈值区间。
- **悬停点位**（触屏可点击、键盘可聚焦）显示：边权、状态（收敛 / 振荡 / 达到上限）、停止轮次和目标值；振荡或上限点无目标值时，改为显示原因（例如“第 N 轮检测到周期约为 2 的持续振荡……不参与 0.5 跨越判断”）。
- 扫描只依赖请求时的画布与参数；任何图编辑或传播参数修改都会使上次曲线失效，重新选择并运行即可。扫描结果不持久化，刷新页面后消失。

## 影响路径追踪

右侧栏的**影响路径追踪**卡片回答“某条证据通过哪些论证链条影响目标结论、影响方向与强弱如何”：

1. 在「起始证据」下拉中选择一个证据节点（在画布上点击证据节点会自动带入）；
2. 在「目标节点」下拉中选择要观察的节点（在画布上点击观点节点会自动带入；起点与目标不能相同）；
3. 可选「最大跳数」1–8，默认 8；点击 **运行路径追踪**。

服务端在请求携带的当前画布图上进行枚举，**只在内存中计算，不保存图、不写 SQLite、不影响画布**：

- **路径模型**：沿有向边做深度优先枚举，深度不超过最大跳数；一条边的符号贡献为支持边 `+weight`、反驳边 `-weight`，路径影响分数 = 路径上各边带符号边权的**乘积**。因此偶数条反驳的路径为**净支持**（分数为正，含 0 条反驳），奇数条反驳为**净反驳**（分数为负）。
- **截断规则**：扩展下一跳时，若该节点已在当前路径上出现则**立即截断**，因此返回的都是无重复节点的简单路径，任何有向环（含自环）都不会进入结果；抵达目标节点的分支也不再经过目标继续延伸。
- **返回结果**：按路径影响分数的**绝对值降序**取前 3 条（同分时跳数更短、节点序列字典序更小者优先）。侧栏依次展示每条路径的排名、净符号徽标、分数与 `|分数|`、跳数、反驳边数，并用链式标签列出**节点标签与逐边关系**（支持/反驳 + 边权百分比；悬停每一跳可看到截至该跳的累计带符号乘积）。
- **画布高亮**：点击侧栏中的某条路径（默认高亮第 1 条），画布上该路径的连线加粗、流动动画并显示累计乘积，起点节点标「起点」徽标、目标节点标「目标」徽标、途经节点整体描边高亮；再次点击可在 3 条路径之间切换。
- 稠密图上简单路径组合爆炸时，枚举设有遍历预算；达到预算会停止并在结果中提示「枚举已截断」，已找到的路径仍然按绝对值排序返回。
- 追踪结果只依赖请求时的画布；**任何图编辑（增删节点/连线、改标签/权重/关系等）或传播参数编辑都会清空追踪结果与高亮**，重新运行即可。结果不持久化，刷新页面后消失。

## 证据贡献分摊

右侧栏的**证据贡献分摊**卡片回答“每个证据对目标观点的最终可信度各贡献多少”——把全部所选证据视为一个联盟，按博弈论 Shapley 值把联盟总效应公平分摊到每个证据：

1. 在「目标观点」下拉中选择一个观点（claim）节点；
2. 在「参与证据」中勾选 **1–8 个**证据（evidence）节点（达到 8 个后未勾选项自动禁用）；
3. 点击 **运行贡献分摊**。

服务端在请求携带的当前画布图上计算，**只在内存中进行，不保存图、不写 SQLite、不影响画布**：

- **联盟重算**：设所选证据为 n 个，则对全部 **2ⁿ 个证据联盟**逐一在内存中复制图副本、**把未加入联盟的所选证据（连同其连线）从副本中删除**，并**沿用当前传播参数**（收敛阈值 / 最大迭代 / λ）重算目标观点的收敛可信度 v(S)。空联盟 v(∅) 为基准，全联盟 v(N) 为总效应终点。
- **精确 Shapley 分摊**：每个证据的贡献 φᵢ = Σ_{S⊆N∖{i}} |S|!(n−|S|−1)!/n! · [v(S∪{i}) − v(S)]，恰好把 v(N) − v(∅) 分摊完毕（非采样近似）。
- **返回内容**：每项**有符号贡献**（正为净提升、负为净压低）、**占比**（贡献 ÷ 总差；总差为 0 时占比无定义，显示 “—”）以及**和式校验**（Σ 贡献 与 v(N) − v(∅) 的差值与是否一致）。分摊项按**绝对贡献降序**排列，并列时按节点 id 升序，结果稳定。
- **收敛门槛**：仅当**全部 2ⁿ 个联盟都收敛**时才给出分摊；任一联盟振荡或达到迭代上限，则整体不可计算，响应列出按联盟掩码升序评估到的**首个失败联盟**（成员、状态、停止轮次与原因），**绝不混用任何末轮值**。

结果展示与交互：

- **瀑布条**：从空联盟基准（灰色虚线）出发，每个证据一格累计条形——正贡献向右（绿）、负贡献向左（红），逐格连接至全联盟值（蓝色实线）；右侧标注有符号贡献与占比。
- **点击高亮**：点击任一条形（或键盘 Enter/空格）可在画布上以紫色描边高亮对应证据节点，再次点击取消。
- **失效规则**：**任何图编辑、分摊选择变化或传播参数修改都会立即清空分摊结果与高亮**；结果不持久化，刷新页面后消失。

限制：证据最多 8 个（2⁸ = 256 次联盟传播，计算量随证据数指数增长）；目标必须是观点节点；图中未选中的证据始终保留在所有联盟副本中，只有“参与分摊的所选证据”才会按联盟增减。

## 必经链路分析

右侧栏的**必经链路分析**卡片回答“哪些节点 / 连线是证据通往目标观点的咽喉要道”——只要移除它，某些证据就再也无法沿有向边影响目标：

1. 在「目标观点」下拉中选择一个观点（claim）节点；
2. 点击 **运行必经链路分析**；
3. 点击任一瓶颈条目（再次点击取消），画布上即高亮**该瓶颈**（琥珀色）、**目标观点**（靛蓝）与**其覆盖的证据**（绿色描边）。

服务端在请求携带的当前画布图上计算，**只在内存中进行，不保存图、不写 SQLite、不影响画布**：

- **瓶颈定义（精确，非路径枚举）**：节点或连线 x 是某证据 e 的瓶颈，当且仅当**删除 x 后 e 无法到达目标**——这等价于“e 到目标的所有有向路径都经过 x”。服务端对每个候选节点 / 连线做一次删除后的反向可达性扫描（从目标沿入边 BFS），因此对任意有向环（含自环、平行边）都严格成立，**绝不靠枚举有限条路径来近似**；证据自身与目标节点不计入瓶颈。
- **覆盖关系**：每个瓶颈附带其**覆盖的证据集合**——这些证据到目标的所有路径都经过它。无法到达目标的证据不参与任何瓶颈，在结果底部**另列**展示。
- **稳定排序**：瓶颈按**覆盖证据数降序**排列，并列时**节点优先于连线**，再按 **id 升序**，多次运行结果一致。
- **结果内容**：`reachableEvidenceIds` / `unreachableEvidenceIds` 为可达 / 不可达目标的证据（均按 id 升序），`bottlenecks` 中每项含种类（`node` / `edge`）、id、覆盖证据 id 列表与覆盖数。
- **失效规则**：**任何图编辑（增删节点/连线、改标签/权重/关系等）或更换目标观点都会立即清空分析结果与高亮**；结果不持久化，刷新页面后消失。分析为纯结构计算，与传播参数无关，修改参数不会使其失效。

## 一键整理布局

点击顶部 **🧭 一键整理布局** 会在**前端内存**中计算新布局并直接在画布上进入**预览**（锁定节点带 📌 徽标与青色描边，未锁定节点的预览位置用琥珀色虚框标出）：

1. **锁定节点**：点击节点右上角 **📍**（再次点击取消），或选中节点后在检查器勾选「整理布局时锁定该节点坐标」。锁定状态随图持久化到 SQLite；
2. 点击 **🧭 一键整理布局**。整理算法固定执行以下步骤：
   - **强连通分量（SCC）压缩**：用 Kosaraju 找出所有强连通分量（有向环内的节点归为同一分量），把每个分量缩成一个超节点，得到一张 DAG；
   - **最长路径分层**：在 DAG 上以最长前驱链长度作为层级，边整体从左指向右；
   - **4 轮重心（barycenter）排序**：向下（以前驱重心）、向上（以后继重心）交替，**固定执行 4 轮**，减少跨层连线交叉；**锁定节点所在分量的纵向位置完全固定，作为相邻层的排序锚点**；
   - **分量内排圆**：同一强连通分量内的节点围绕分量中心排在等角圆上（按跨分量连接方向选择旋转角），单节点分量不排圆；
   - 最后做纵向松弛与碰撞兜底，保证未锁定节点彼此不重叠、也不压到锁定节点；
3. **预览指标**：画布顶部预览条展示整理前后的**连线交叉数**（`前 → 后`，下降时标绿）、未锁定节点的**总位移**、移动节点数与锁定节点数；
4. **确认 / 取消**：
   - 点击 **✓ 确认应用**：一次性把新坐标写入画布，并沿用现有自动保存逻辑（防抖 `PUT /api/graph`）保存到 SQLite；
   - 点击 **✕ 取消**：画布恢复进入预览前的坐标，**不保存、不改写画布、不写 SQLite**；
   - 预览期间不能增删节点 / 连线、拖拽、连线或编辑任何图属性（检查器整体禁用）；**任何图编辑都会使预览失效**，需重新点击整理。

**不变量保证**：

- 锁定节点坐标**逐位不变**（多锁定节点同处一个环时，环的中心取锁定位置均值，未锁定成员绕该中心排圆）；
- 整理后所有节点坐标均为有限数；
- 未锁定节点之间、未锁定节点与锁定节点之间均不重叠（锁定节点之间若原本重叠则保持原状）；
- 交叉数按节点中心之间的直线段严格相交统计（共端点、共线、自环不计）；总位移只统计未锁定节点的移动距离之和。

整理只改变节点坐标，不改变节点、连线、权重或可信度，因此不会清空已有的传播分析与回放结果；布局结果本身不产生额外的服务端请求。

## 传播模型

设节点 $i$ 的先验可信度为 $p_i$，当前可信度为 $b_i$，则每轮同步更新：

\[
b_i^{(t+1)} =
\operatorname{clip}_{[0,1]}\left(
p_i + \lambda\left(
\sum_{e:j\to i,\ support} w_e b_j^{(t)}
-
\sum_{e:j\to i,\ rebut} w_e b_j^{(t)}
\right)\right)
\]

- `λ`：传播强度，默认 `0.8`；
- 支持边提高目标可信度，反驳边降低目标可信度；
- 被标记为“固定”的节点始终保持初始可信度；
- 当最大节点变化小于收敛阈值时判定收敛；
- 系统比较最近若干轮的状态向量，发现稳定周期即判定振荡；
- 振荡检测后枚举有向简单环，优先报告具有奇数条反驳边、负增益较强且近期仍在移动的环。

这是一个带先验锚定的线性加权意见传播模型。强负反馈环（例如全强度的三角相互反驳）会产生持续周期；先验与默认传播强度通常会让常规论证图稳定。

## JSON 格式

导出的文件结构如下：

```json
{
  "version": 1,
  "name": "我的论证图",
  "nodes": [
    {
      "id": "e1",
      "label": "实验证据",
      "kind": "evidence",
      "initialBelief": 0.8,
      "anchored": false,
      "positionLocked": false,
      "position": { "x": 100, "y": 80 }
    }
  ],
  "edges": [
    {
      "id": "edge-1",
      "source": "e1",
      "target": "c1",
      "stance": "support",
      "weight": 0.7
    }
  ]
}
```

约束：

- `kind` 只能是 `claim` 或 `evidence`；
- `stance` 只能是 `support` 或 `rebut`；
- `initialBelief` 与 `weight` 必须在 `0..1`；
- `positionLocked` 为可选布尔值（缺省视为 `false`），为 `true` 时一键整理布局不会移动该节点；
- 节点 id 必须唯一，连线两端必须引用已存在节点；
- 导入时后端会进行严格校验并返回明确错误。

## HTTP API

- `GET /api/health`：健康检查；
- `GET /api/graph`：读取当前图；
- `PUT /api/graph`：整体替换并持久化当前图；
- `POST /api/propagate`：在当前持久化图上运行传播。响应中的 `result.traces` 记录每个节点第 0 轮到停止轮的逐轮可信度（传播回放的数据来源），`result.options` 为本次实际使用的传播参数。
- `POST /api/sensitivity/edge-weight`：边权敏感性扫描。请求体必须携带当前画布图 `graph`，服务端仅对其做严格校验并在**内存**中逐点计算，**不会保存或修改持久化图**；另外携带 `edgeId`、`targetNodeId`、`options` 与可选的 `samples`（默认 21，范围 2–101）。响应 `scan.points` 为每个等距边权一个点，含 `weight`、`status`（`converged` / `oscillating` / `limit`）、`iterations`、`targetValue`（振荡点为 `null`，原因见 `reason`）、`detectedPeriod`、`maxChange`；`scan.thresholdBand` 为首个由两个相邻收敛点构成、目标值首次跨过 0.5 的区间（无则为 `null`），振荡/未收敛点不参与判断。
- `POST /api/trace/influence-paths`：影响路径追踪。请求体必须携带当前画布图 `graph`（严格校验后仅在**内存**中枚举，**不会保存或修改持久化图**）、起始证据节点 `startNodeId`（其 `kind` 必须为 `evidence`）、目标节点 `targetNodeId`（不得与起点相同），以及可选的 `maxHops`（默认/上限 8，范围 1–8）。响应 `trace.paths` 为按 `absoluteScore` 降序的至多 3 条路径：每条含 `nodeIds` / `edgeIds` / `hops`、逐边 `steps`（`edgeId`、`sourceId`、`targetId`、`stance`、`weight`、截至该跳的 `runningScore`）、路径总分 `score`（支持边 `+weight`、反驳边 `-weight` 的乘积）、`absoluteScore`、净符号 `sign`（`support` / `rebut`）与 `rebutCount`；`trace.enumeratedPaths` 为遍历预算内抵达目标的简单路径总数，`trace.truncated` 表示是否因预算上限提前截断。
- `POST /api/shapley/evidence-contribution`：证据贡献分摊。请求体必须携带当前画布图 `graph`（严格校验后仅在**内存**中计算，**不会保存或修改持久化图**）、目标观点 `claimNodeId`（其 `kind` 必须为 `claim`）、1–8 个证据 `evidenceNodeIds`（均须为 `evidence`，不得重复），以及可选的 `options`（缺省沿用默认传播参数）。服务端对全部 2ⁿ 个联盟在图副本中删除未加入联盟的所选证据后重算传播。响应 `shapley.computable` 为 `true` 时：`baselineValue` / `fullValue` / `totalDifference` 为空联盟基准、全联盟值与差值，`contributions` 为按 `|contribution|` 降序、节点 id 升序排列的分摊项（各有符号贡献 `contribution`、`absoluteContribution` 与占比 `share`，总差为 0 时 `share` 为 `null`），`sumCheck` 给出 Σ 贡献与差值的和式校验；`computable` 为 `false` 时上述字段均为 `null`，`failure` 列出首个失败联盟（`evidenceIds`、`status`（`oscillating` / `limit`）、`iterations`、`reason`），不使用任何末轮值。`coalitionCount` 为重算的联盟总数，`options` 为实际使用的传播参数。
- `POST /api/bottleneck/mandatory-links`：必经链路分析。请求体必须携带当前画布图 `graph`（严格校验后仅在**内存**中计算，**不会保存或修改持久化图**）与目标观点 `targetNodeId`（其 `kind` 必须为 `claim`）。服务端对每个候选节点 / 连线做“删除后反向 BFS”判定：删除某元素后原本可达目标的证据变得不可达，则该元素是这些证据的必经瓶颈（等价于“所有有向路径共同经过”，对环严格成立，非路径枚举近似）；证据自身与目标不计瓶颈。响应 `analysis.reachableEvidenceIds` / `unreachableEvidenceIds` 为可达 / 不可达目标的证据 id（按 id 升序，不可达者另列）；`analysis.bottlenecks` 为瓶颈列表，按覆盖证据数降序、节点优先于连线、id 升序稳定排列，每项含 `kind`（`node` / `edge`）、`id`、`coveredEvidenceIds`（按 id 升序）与 `coveredCount`。
